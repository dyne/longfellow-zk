# CMake package migration and release qualification

`liblongfellow-zk` is the base package.  ECDSA, BIP340, mdoc, and BlindZap are
separate CMake projects and packages; base headers never include named-circuit
headers.  Release artifacts contain the static archive, versioned shared
library (or macOS dylib), exported CMake targets, explicitly listed headers,
license, ABI policy, and a SHA-256 checksum.  BlindZap is built and distributed
separately because its GPLv3+ licensing and dependency metadata differ from the
Apache-2.0 base package.

## Consume an installed package

```cmake
find_package(LongfellowZK CONFIG REQUIRED)
add_executable(app app.cc)
target_link_libraries(app PRIVATE LongfellowZK::shared) # or ::static
```

Configure a consumer with `-DCMAKE_PREFIX_PATH=/path/to/prefix`.  On ELF
systems, make the shared library discoverable through the platform loader
configuration (for example, an application rpath or an approved loader path),
not a source-tree path.  The package is relocatable: consumers must not add
`src/`, `projects/`, or build directories as include or link paths.

## Build and cross-compile

Use `cmake --preset release`, `debug`, or `sanitizers`; the retained
`GNUmakefile` is a deprecated forwarding interface only.  `cmake --preset wasi`
uses `cmake/toolchains/wasi.cmake` and `WASI_SDK_PATH` (default `/opt/wasi-sdk`)
to build the static base library.  It deliberately does not claim that native
CTest executables can run under WASI.

## Extraction, ABI, and rollback

Projects are already independently configurable against an installed base
prefix, so extracting one preserves exported target names and include contracts.
The base ABI is pre-1.0 (`0.1.0`, SOVERSION `0`): source and protocol
compatibility are tested, but cross-toolchain C++ ABI stability is not promised.
To roll back, deploy the prior monolithic release and retain its loader paths;
do not mix its headers with the split package libraries.  Protocol vectors and
proof artifacts remain validation inputs and are never regenerated by packaging.

## Release gate

Run `bash scripts/ci-installed-package.sh` from a clean checkout.  It builds,
tests, installs, relocates and independently consumes the base package, then
configures/tests/installs ECDSA, BIP340, mdoc, and BlindZap against that prefix.
CI also runs the platform-specific WASI, macOS, sanitizer, static-analysis,
Rust, Sage, and real-proof jobs where those toolchains are available.
